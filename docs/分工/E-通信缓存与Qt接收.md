# 分工 E：通信、终端缓存与 Qt 接收

## v0.2 功能编号与主责

本岗位唯一主责：**C-01 TCP、鉴权与 JSON Lines 收发、C-02 ACK、去重与断网补传**。A 提供分钟汇总，H 提供事务保存结果及数据库去重，F 提供连接配置与状态界面；协作不改变本功能唯一主责。

功能编号前缀表示功能模块，不等于人员岗位字母；例如 C-01 的负责人是 E。以下仍为任务计划，本轮未将功能标记为实现或验收通过。

## 我的职责与文件

让 A 生成的分钟记录可靠到达 H 的 SQLite，并向 F 提供连接／接收状态。设备断网时仍由 A—D 完成本地功能，E 负责待传记录及恢复同步。

计划归属：`firmware/components/transport/`、`firmware/components/record_cache/`、`desktop/src/network/`；以及 `tests/E/`、`docs/modules/E/`、`evidence/E/`。公共协议位于 `contracts/`，由 A 主维护，E 与 H 共同核对。实际目录以组内工程基线为准。

## 输入、输出与协作

- 输入：A 的标准记录；网络配置；H 返回的“已提交／已存在／失败”结果。
- 输出：设备待传状态、Qt 解析后的记录、确认／重发结果及连接状态。
- 与 H 先对齐记录标识（建议设备＋会话＋序号）、落库与确认顺序；与 F 对齐展示状态。字段名、鉴权与缓存参数以总约定及课堂模板确认，不能各写一套。
- 向 F 提供连接参数、建立／断开操作和状态接口；IP、端口及设备标识从配置传入。TCP 两端的监听／连接角色尚待对齐，不在界面或协议草案中擅自固定方向。

## 任务清单

**E0．先定边界。**整理 JSON Lines 样例、鉴权、消息标识、确认／重发和错误处理草案，交 A／H 核对。验收：发送方、接收方、存储方能解释同一条记录的完整路径。

**E1．打通接收。**建立可配置的 Wi-Fi TCP 链路、鉴权与按行缓冲解析，覆盖半包、粘包、一次收到多行及非法 JSON。验收：有标记的测试记录正确解析，非法鉴权被拒绝，错误行不会阻塞后续有效行。

**E2．接缓存与入库确认。**离线保留未确认队列，按确认的超时规则重发，恢复后补传；H 持久化成功后才确认，重复记录按 H 的已存在结果正确应答。验收：注入丢 ACK、超时、重复发送及存储失败，确认可重发且不增加重复行；存储失败不被误报成功，缓存记录保留原设备／会话／序号。

**E3．真实数据联调。**接 A 的真实步数记录，与 H／F 核对保存和展示。验收：保留半包、重复包、断网恢复日志和两端数量／序号对账；本地计步与提醒在断网时继续运行。

## 提交证据与边界

交付协议样例、故障测试输入、发送／接收／确认日志和联调记录。缓存介质、容量、满载策略及断电保持要求待确认，先写清实际能力，不承诺无限补传。测试／模拟／真实数据必须可区分，最终验收用途按课程说明执行。

E 不负责算法、页面布局或建表；H 不直接改 E 的解析流程。发现公共边界问题先记录并同步 A 和受影响成员。
