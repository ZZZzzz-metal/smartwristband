# 分工 G：健康传感器扩展与数据质量

## v0.2 功能编号与主责

本岗位唯一主责：**X-01 温度趋势、X-02 心率血氧趋势（均为 P1）**。P0 阶段继续协助 B 的器件、自检与异常验证，并协助 C 的实走复测；不改变 B／C 对相关功能的唯一主责。

本轮以功能表为准：X-02 保留真实 MAX30102 心率／血氧趋势目标。需求表 R16 的模拟心率趋势作为前期展示用例，模拟趋势、真实器件采集及有效心率／血氧输出分阶段记录、分别验收，不用模拟输出充当真实器件证据。

功能编号前缀表示功能模块，不等于人员岗位字母。以下仍为任务计划，本轮未将功能标记为实现或验收通过。

> **给 AI 的开场白（复制粘贴）**：你在开发 ESP32-S3 智能健康手环，我负责分工 G。请先读[总约定](00-总约定.md)、[需求与验收](需求与验收.md)、[架构与界面草图](架构与界面草图.md)，再读本文。温度、心率和血氧是选做，按“温度先行、心率血氧随后”独立调试。只修改归属目录，复用 B 的公共总线接口；不要更改核心采样、全局配置和必做界面。一次处理一项任务，并区分代码检查与真实器件验证。

## 我的职责与文件

为 TMP117、MAX30102 提供可接入的健康趋势数据和有效性状态，并保留实测证据。早期协助 B 核对器件、自检和异常场景；全组各自负责模块测试，G 不承担全项目唯一测试员。

计划归属：`firmware/components/health/`、`tests/G/`、`docs/modules/G/`、`evidence/G/`。共享 I²C 驱动由 B 维护；扩展字段由 A 维护的共享约定统一，D／F 负责展示、E 负责传输、H 负责保存。

## 输入、输出与协作

输入为实际模块、B 的 I²C 接口和采集时间基准；输出为温度、心率／血氧及各自状态，例如未启用、采集中、有效、无效或器件失联。不可用数值使用 `null` 并保留状态，不用 0 代替。模块版本、地址、电平和引脚按实物核对，不套用其他平台的整套接线。

## 任务清单

**G0．资料与器件表。**核对 TMP117、MAX30102 模块及参考代码来源，列出待移植接口与接线疑点；早期协助 B 留存连续上电自检、器件缺失／失联证据，协助 C 按 5 组×100 步、每组误差不超过 3 步的标准实走复测。验收：B 能据此安排实物调试，C 可核对独立复测记录；未知引脚或驱动条件明确留空。

**G1．温度独立调试。**先读取并换算 TMP117 温度，形成连续记录和失联状态。验收：有真实样本、采样条件与变化记录；模块温度不直接标为准确人体核心体温。

**G2．心率血氧独立调试。**先按需求表 R16 准备明确标记为模拟的心率趋势与无效状态；真实 MAX30102 初始化、FIFO 读取和参考算法作为 X-02 器件实验单独准备，保留原始光学样本及计算有效性。验收：模拟展示与实物实验分开留证，采集、接触、有效、无效及失联状态可解释；真实心率／血氧没有稳定证据时保留为实验目标，不报已完成。

**G3．逐项接入。**与 A 确认启用方式，再请 D／E／F／H 接数据。验收：选做关闭、失败或失联时，计步、久坐、界面和上传主线继续运行；接入后复测受影响必做项。

## 提交证据与边界

提交器件表、接口说明、原始／处理样本、有效性和失联记录、演示截图或录屏。数据来源须标记；课件中“模拟数据”与真实步数实测的适用阶段待说明，不能以模拟值冒充真实测量。

G 不做医疗诊断、治疗建议或电池充电设计。跌倒算法归 C，G 可以协助记录测试；移动端／云端不挤占此阶段。选做只有独立调试成熟且必做不受影响时才合入。
